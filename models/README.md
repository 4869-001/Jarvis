# 唤醒词模型与词表

- `kws-zh-en/` —— `sherpa-onnx-kws-zipformer-zh-en-3M-2025-12-20`，中英双语，约 3M 参数
- `kws-jarvis.txt` —— 音素词表

## 词表格式

```
音素序列 :提升分 #阈值 @显示名
```

中文用带声调拼音，英文用 CMU ARPAbet（对照 `kws-zh-en/en.phone`），
两种混在同一文件，一个模型同时听。**加词只改这个文件，不需要重训模型。**

> ⚠️ **这个文件里不能写注释。** `#` 是阈值标记，不是注释符；
> 加了 `#` 开头的行会让整份词表解析失败，症状是「一个词都不触发」。

## 当前参数怎么来的

2026-08-01 在 20 条 TTS 语料上扫出来的（9 条正样本 / 11 条负样本），
最终 **命中 8/9，误触 1/11**。唯一的误触是 "Java script is a language"。

扫过但更差的方向，别再走一遍：

| 方向 | 结果 |
|---|---|
| 抬提升分（`:` 3.0→4.0） | 误触上升，召回不升 |
| 放宽 `max_active_paths`（4→8→16） | 召回 6→7→8，但误触 0→3→6，完全不能用 |
| 整体抬阈值（`#` 0.02→0.5） | 召回掉得比误触快 |
| 删掉非儿化变体 | 英文召回 8/9 → 6/9 |

## 英音那两条为什么阈值不一样

最后两行 `JH AA1 V IH0 S` / `JH AA1 V AH0 S` 是**非儿化**发音
（英音 /ˈdʒɑːvɪs/，R 不发音）。定稿的英文音色 `jarvis-high` 是 en_GB，本来就不发 R，
所以这两条是英文召回的关键——删掉它们英文就基本不触发了。

但它们和 "Java" 的 `JH AA1 V AH0` 撞车，所以阈值单独抬到 `0.25`：
再往上（0.35+）英文召回断崖式下跌，往下 "Java script" 之类会误触。
这是真实的声学冲突，改音素消不掉，只能选工作点。

## 改完怎么验

```bash
# 生成语料（需要 voices/.venv）
cd voices && .venv/bin/python synth.py zh "贾维斯" --raw --out /tmp/x.wav
ffmpeg -i /tmp/x.wav -af "adelay=600|600,apad=pad_dur=1.2" -ar 16000 -ac 1 -f f32le /tmp/x.raw
```

**样本尾部必须补静音。** 流式解码要靠尾部空白帧把命中定稿；
音频一喂完就没有后续帧，短样本会永远不触发——这不是词表的问题，是测试方法的问题。

真机实测仍需覆盖：安静环境漏唤醒率、音乐播放时误唤醒率、0.5m/1m/2m 距离、
中式英语发音。Jarvis 自播报时的误触发已由半双工门挡住。
